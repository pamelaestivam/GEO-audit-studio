# Independent review: GEO Audit Studio at `2b5498b` (PR #18) and the product as a whole

Date: 2026-10-09. Written to be read cold. Reviewer: a Claude session that did not
write the code under review, with fresh-context sub-agents (adversarial-reviewer,
ux-tourist, a research agent). **They are the same model family as the author of
the code, so none of this is an independent human review** (see Part B, 7).

**Evidence labels.** **MEASURED**: I ran it and saw the output. **READ**: I read the
code or document, did not run it. **INFERRED**: reasoned, not observed. **AGENT**: a
sub-agent reported it from a web search and I did not open the source myself; treat as
INFERRED until someone opens the link. Every number from a price page is AGENT.

## 0. Verdict

The foundation holds where the previous session aimed its tests: sign-in, ownership,
admission, restart survival and the honesty of failure states all survived hostile
probing (section 1). The defects are in two places its tests did not reach: **the
metrics' edges** (a brand the product reports as 0% when engines name it in every
sentence; an accuracy number computed from the wrong denominator) and **everything
that has only ever met a fake** (three engine adapters with no test at all, a default
Claude model that retires in seven weeks, docs that were never run literally).

Nothing here has touched a real answer engine, and neither has the previous session.
**The product's central claim, that a score measures how a brand appears in AI answers,
is unproven until one real audit has been read by a human against the raw answers.**

Baseline (MEASURED): `npm ci && npm run verify` on `2b5498b`: exit 0, 861 `pass`
lines, no `FAIL`, lint clean, `npm audit` 0 vulnerabilities.

## 2. Confirmed defects (ranked)

(D1 to D8 below are this report's defects. References to "MVP_AUDIT decision D1 to D4" mean the owner decisions in `docs/MVP_AUDIT.md`.)

### High

**D1. A brand with a two-character name reads 0% and gets a remediation plan** (MEASURED). `findFirstMention` skipped every token under 3 characters. `HP`, `3M`, `EY`, `GE`, `BP` named in every sentence: `mentioned=false`. The previous round fixed the sibling `queryNamesBrand` for HP/3M but not the scorer. Impact: a failure to measure reported as a finding about the client. Fix: PR #19 (acronyms matched exactly as written; ordinary words like "On" deliberately not). Remaining limits in `TECH_DEBT.md` 2.6c. Effort: done.

**D2. Fact Accuracy Rate used the wrong denominator and invented attribution** (MEASURED against the built server). `(mentions - claims) / mentions`: two claims about one of two mentioning answers read **0%**; per answer it is 50%. A claim naming a query that was never asked, or an engine never measured, was re-attributed to query 1 / engine 1 and lowered the score. Fix: PR #21 (per-answer; the narrative prompt numbers each query; claims that cannot be tied to an answer naming the brand are discarded and the user is told; the tile says "at most this" when any were). It is still a *shape* check: nothing verifies that the claimed fact appears in the answer (`TECH_DEBT.md` 2.5a). Effort: done.

### Medium

**D3. "Named in N of M answers" counts a brand that was only *cited as a source*** (MEASURED at function level; not fixed). `mentioned = named-in-text OR own-domain-cited`. An answer that never names the brand but cites its site scores visibility 100%, status "secondary mention", rank null, excerpt empty. The card's wording is "Named in", the narrative prompt says "Cited in". Two defensible metrics are being conflated. **Owner question Q1.**

**D4. Spend is not capped in dollars, and the per-code audit budget is not the biggest door** (MEASURED for counts; prices AGENT).
- `evaluate-query` ("Add & Audit Query") costs one grounded call per engine and is limited only by `USER_LOOKUPS_PER_HOUR=30` per code, **in process memory, reset by a restart** (30 accepted, 5 refused, then a restart allowed another). That is up to 720 calls/day/code against an audit allowance of 10 audits x 3 queries = 30 calls/day/code: **24x**. There is no global lookup cap.
- Failed audits are free and unbounded (known, `TECH_DEBT.md`): with a 3/day budget, 6 audits whose prompt was blocked were all admitted (18 grounded Gemini calls, none counted).
- The only real ceiling is the Gemini pacer (`GEMINI_MIN_INTERVAL_MS=6500`, ~13,300 calls/day), about **$219/day or $6,570/month** if every call were billed at the AGENT price of $0.0165 per grounded call. That is an accident of pacing, not a control.
- The pacer is one global FIFO queue: 30 lookups by one person put every other user's audit ~3 minutes behind (READ).
- Budgets count audits, not calls: `MAX_AUDIT_QUERIES=8` x four engines is 32 grounded calls for one "audit".
Proposed fix (needs an owner decision on semantics, Q2): count lookups in the durable store and give them a daily per-code and global cap; add `MONTHLY_CALL_BUDGET` enforced from the store; count a failed audit as billable when any engine call was dispatched, or cap non-billable failures per day. Effort: 1 to 2 days.

**D5. Accented vendor names were truncated or lost** (MEASURED). "Café Lumière" became `Caf`, "Nestlé" `Nestl`; "Zoë Group" vanished. Fix: PR #20. Hyphenated and digit-led names still truncate ("Coca-Cola" -> "Coca"), `TECH_DEBT.md` 2.6d.

**D6. The three non-Gemini adapters had no test, and had real faults** (MEASURED with fixtures written from vendor docs, not recordings): an HTTP-200 Anthropic search failure (error *object* as `content`) threw and discarded a written answer; text blocks concatenated with no separator; a `max_tokens`/`pause_turn` answer returned as a clean answer; quota advice (Pacific-midnight reset, AI Studio link) printed for every provider; a retired model id and an out-of-credit account both read as "unexpected error / wait a minute". **The default `claude-sonnet-4-5` is deprecated 2026-09-30 and retires 2026-11-30** (AGENT, quoting Anthropic's model-deprecations page): on that date every Claude observation silently becomes a failed lookup. Fix: PR #22.

**D7. A plain copy of the database restores an empty database** (MEASURED). WAL mode: one finished audit was 119 KB in `-wal` beside a 4 KB main file; restoring only `geo-audit.sqlite` showed 0 audits. `DEPLOYMENT.md` said "everything is in `DATA_DIR/geo-audit.sqlite` (plus `-wal`/`-shm` while running)" and offered `sqlite3 .backup`, a CLI the `node:22-slim` image does not ship (READ from the Dockerfile base); it mentioned the WAL files but gave no way to copy them consistently. Fix: PR #24 (`scripts/backup.mjs`, run by CI inside the container, restore steps).

**D8. After a reload, Add-query and tick-task did nothing; Auto-Detect filled a guessed domain** (MEASURED by the ux-tourist). `activeAuditId` is null after a load while the newest audit is shown, and both handlers returned on it. Auto-Detect set `acmewidgets.com` from the typed name, under a notice saying nothing is guessed. Fix: PR #25. These edits are still never persisted (the card now says so).

### Low

- Tracked competitors are silently dropped when their name contains the client's (`Square Enix` beside `Square`, `BP Pulse` beside `BP`) and are hidden when no engine named them (a 0% rival is information) (MEASURED at function level).
- Narrative text can contradict the computed numbers on the same card (ux-tourist saw "named in 2 of 3" beside "Named in 3 of 3"); nothing checks narrative numerals against the metrics. **Owner question Q3.**
- "Verified Actual Fact: 'Unknown'" in a green box, and "Origin Source: Direct LLM Parametric Memory", are model assertions presented as verified (ux-tourist).
- Tokens: no per-session revocation (logout is client-side), 7-day lifetime in `localStorage`, no CSP; removing then re-adding a code revives old tokens.
- Phone layout (ux-tourist, MEASURED): module titles hidden under the ~220 px sticky header after tapping a module; the headline score scrolled off after an audit finishes; the Export modal clips the score box and overlaps two labels; the query table clips the engine column. Not fixed here.
- Monitoring preview: honest banner, but the toggle is on by default, example email addresses are prefilled as the user's own, and "Preferences saved" saves to React state only.
- `index.html` title was "My Google AI Studio App" and `metadata.json` named the product "Remix Remix AI Search Audit & Remediation Platform" (fixed in #24).
- Gemini lookups combine `googleSearch` with `responseMimeType: application/json` + a schema. Older Gemini models rejected that combination; whether `gemini-3.6-flash` accepts it is unverified (INFERRED).

## 4. Product-level concerns (Part B)

**1. Is the core measurement valid?** *Not yet demonstrable.* The headline is a share of 3 answers (one engine, one run). Possible values are 0, 33, 67, 100. 95% Wilson ranges (MEASURED by script, outward-rounded): 0/3 -> 0-57%, 1/3 -> 6-80%, 2/3 -> 20-94%, 3/3 -> 43-100%, 5/10 -> 23-77%. About 97 independent answers are needed for +/-10 points at 50%. Published evidence on run-to-run variation is blog-level and was not opened by me (AGENT): a SparkToro/Gumshoe study reports 2,961 runs of 12 prompts with fewer than 1 in 100 runs producing the same brand list, while a stable core of brands recurs; a preprint titled "Don't Measure Once" argues for treating visibility as a distribution; I found no firm repeat count. The previous session's own guide says "run it twice". The product *was* honest about n ("Named in 3 of 3 answers", "indicative") but invited over-reading with a colour ring and a bare "100%" in three other places. Smallest change that makes the uncertainty visible: PR #23 (range beside the score, badges carry "(3 answers)", neutral ring under five independent readings). A real fix needs repeated runs per query (cost scales linearly) and paraphrased queries; that is the roadmap's item 8 and MVP_AUDIT decision D4.

**2. Is the data what users think it is?** *No, and it was never said.* A grep of `src/`, README and USER_GUIDE found no statement that the numbers come from the engines' *developer APIs* rather than the consumer apps (models, personalisation, location and system prompts can differ; AGENT found no rigorous comparison and one vendor claim that Gemini is grounded on ~41% of API answers versus ~98% of AI Mode). The report also recorded neither model ids nor capture times. Fixed in PR #23 (disclosure on card and export, `engineModels`, capture times) and #24 (USER_GUIDE). The Chrome "AI Mode" claim in `DEPLOYMENT.md` 10 is correctly "considered, not built".

**3. Cost and quota.** Calls per audit: `Q x N` grounded calls plus one narrative call (MEASURED: 3 grounded + 1 narrative for the default audit on Gemini; 18 grounded calls for 6 three-query audits). Prices are AGENT-level except Anthropic's, and cannot be treated as quotes. At the AGENT prices a default audit (Q=3, N=1) is ~$0.06, Q=8, N=1 ~$0.15, Q=3, N=4 ~$0.19 to $0.21, Q=8, N=4 ~$0.48 to $0.54. With the 100-audits/day global cap binding for 30 days the AGENT arithmetic gives ~$190, ~$437, ~$570 to $633 and ~$1,450 to $1,620 a month, and every real input-token count for the web tools is higher than the 300 assumed. **There is no hard monthly ceiling anywhere in code**; see D4 for the doors the audit budget does not cover. Gemini 3.6 Flash token prices are said to rise on 2027-01-01 (AGENT).

**4. Single points of failure.** One process, one SQLite file, one Gemini key, one global Gemini queue. 10x load on the *read* path is fine (MEASURED, section 1); the ceiling is the pacer (about 9 calls/min, so about two default audits a minute for everyone) and quota. Key revocation or provider outage: audits fail with a sentence and are non-billable, readiness shows it; nothing alerts the owner. Backup: none before #24, and the obvious copy was broken (D7); off-host copy and scheduling remain manual. Restart mid-audit: job failed with a sentence (MEASURED), not resumed.

**5. Security and privacy.** Authentication and ownership held (section 1). No server-side fetch of user-supplied URLs exists (READ: `parse-url` only builds a string), so no SSRF surface. Stored XSS through evidence or link fields: refuted for `javascript:` (React 19), but there is **no CSP** and the session token sits in `localStorage` for 7 days, so any future XSS is a token theft. Prompt injection cannot reach another user's data and cannot change a deterministic metric, but can change the accuracy count and any link or narrative text the model emits (the model is also what writes the "Target Deployment URLs"). Personal data: the email is stored inside the ownership key in `jobs` and `audits`; job rows are pruned after 7 days, **saved audits never expire**, and the only deletion is per-audit by its owner, with no "delete my account" and no Terms or Privacy page (roadmap 20). Brand and competitor strings are sent to Google (and OpenAI/Perplexity/Anthropic if enabled); the product does not say so (INFERRED: I did not search every string).

**6. Product fit.** The user is a marketer or agency lead who must show a client "are we in the AI answers, and what do we fix". The honest parts (failure shown as a dash, "not assessed", only measured engines) are the product's strongest asset and held up in every probe. What would make them *distrust* it: a number that moves between two identical runs with no explanation; a narrative that contradicts the card (seen); a "Verified" label on a model's guess; remediation advice presented as expected gain. Roadmap status as I read it: 4 of 20 items are fully done (2, 4, 12, 16); item 14 is marked done but is true only for Gemini (readiness never calls the other engines); the other 15 are partial or open. MVP_AUDIT decisions D1 to D3 were *taken by the builder "in the owner's absence"* and are framed as already decided; MVP_AUDIT decision D4 (engines and money) is the only one that decides spend and is correctly left to the owner; it does ask for "which keys you will pay for and a monthly ceiling", but frames the ceiling as a choice of keys and no mechanism enforces a dollar figure (D4 below, Q2). MVP_AUDIT decision D1's "roughly $5-10/month" host price contradicts `DEPLOYMENT.md`'s "prices are not stated here"; neither was checked.

**7. Is the process gate independent?** *No, it is self-grading.* READ: the "agents" in `.claude/agents` are prompts that the authoring session invokes; PR #18 shows the EVAL PM composite (87, SHIP) written in `docs/MVP_AUDIT.md` by the builder, and the PR was merged by the owner with no recorded review on the PR page that I inspected (I read the PR body and CI runs, not every review). Branch protection is described as an owner action and I cannot see the setting. This review has the same limit: the reviewers I used share my model family, though they were useful (the first-round reviews of my own fixes #19 to #24 all came back FIX BEFORE MERGE with a real defect in the fix). To make it a control: require CI and **one human approval** on `main` (branch protection); CODEOWNERS on `src/analysis.ts`, `src/auth.ts`, `server.ts`; have the reviewer run on a *different model* and post its verdict as a PR check the author cannot edit; run mutation testing on `src/analysis.ts` and `src/auth.ts` in CI so "the test fails when the code is wrong" is measured, not claimed (13 of 14 here); store the EVAL PM verdict as a CI artifact tied to the commit SHA.

## 8. Try to break it (verified start-up, then a list of things worth attacking)

**Start-up, run on the merged `main` with no API key (MEASURED):**

```
git clone https://github.com/pamelaestivam/GEO-audit-studio && cd GEO-audit-studio
npm ci                          # Node 22.13 or newer
cp .env.example .env.local      # put YOUR OWN Gemini key in GEMINI_API_KEY; never commit it
npm run dev                     # http://localhost:3000, any email + the code "dev-access"
```

To sign in from a script, POST `/api/auth/login` with `{"email": "you@example.com", "accessCode": "dev-access"}` (the field is `accessCode`, not `code`) and send the returned token as `Authorization: Bearer <token>`.

With no key the app starts, `/api/audit/status` lists no engines and an audit says so in
words instead of inventing a score; that is the first thing to look at. With a key, one
default audit costs about 3 grounded Gemini calls plus one narrative call (MEASURED
against the fake endpoint; real prices are unverified). **Nothing in this review has run
against a real engine**, so a real audit is the most valuable test there is: read the raw
answers on the Evidence tab against the score the card gives.

For a production-shaped run: `npm run build`, set `SESSION_SECRET` (32+ characters) and
`ACCESS_CODES="you=a-long-code"`, then `npm start`; check it with
`node scripts/smoke.mjs <url> --email you@example.com --code a-long-code`.

**Things worth attacking, in the order I would:**

1. **A brand with a two-letter name** (HP, 3M, EY, BP): it should be measured, not read as 0%
   (D1). Then a brand that is an ordinary word (On, Go, It): it should stay conservative.
2. **Accented and non-Latin names** (Café Lumière, Nestlé, Яндекс, a name typed with
   combining accents): names should appear whole in vendors and in share of voice (D5).
3. **A blank domain**: type only a name, press Auto-Detect with a lookup that finds nothing
   (or just leave the domain empty). Nothing should be filled in as a guess, and "not
   measured, no domain was given" should appear instead of a false "not cited" (D8).
4. **Reload, then add a query and tick a remediation task.** It should work, and the card
   should say those edits live in this tab only (D8).
5. **Read the score with suspicion.** The card should show a range, "(N answers)" on the
   badge, a grey ring under five independent readings, a "How this was measured" box and
   the model ids; check the same words in Export and Copy Summary (D-series, Part B 1 and 2).
6. **Inaccuracies tab**: every claim should name a real query and engine; a note should say
   how many were left out because they could not be tied to an answer, and the accuracy
   tile should say "at most" when any were (D2).
7. **Money and abuse**: run many "Add & Audit Query" lookups, restart the server in between,
   and run audits that fail. None of it is capped in dollars (D4, owner question Q2).
8. **Backups** (with `DATA_DIR=./data` set, which `npm run dev` does by default): run an audit, then `node scripts/backup.mjs ./data` while the server is
   running; restore the file per `docs/DEPLOYMENT.md` and confirm the audit is back.
9. **Sign-in**: wrong codes, many tries from one address, an edited token, a second email on
   one code (see section 1 for what already held).
10. **Phone width**: module titles under the sticky header, the Export modal, the query table
    (known layout problems in the Low list; not fixed here).
